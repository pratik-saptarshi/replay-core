Phase 0 Implementation Plan — replay-core: Canonical-Digest Law & Conformance Fixtures

Produced under the feature-pr-pipeline skill (Stage 1, writing-plans). For agentic workers: REQUIRED SUB-SKILL — subagent-driven-development (fresh implementer + task reviewer per task), test-driven-development inside each task. Steps use checkbox syntax for tracking.

Goal: Establish the byte-exact canonical-digest law for replay-core — a Go canonical-JSON encoder and record/witness digest API whose outputs match the conformance corpus's frozen vectors bit-for-bit — plus the versioned conformance corpus that gates it in CI forever. No runtime, no store, no replay in this phase.

Architecture: Two canonical profiles are adopted and both are in scope: replaycore.kernel.canonical.v1 (trace records; raw UTF-8, Python json.dumps semantics) is the primary law for F2's store; commons.canonical.v1 (ASCII-escaped, floats forbidden) is the secondary profile. A language-neutral JSON corpus under testdata/corpus/ — golden vectors, law-test cases, and shipped vectors generated from the reference law suite — is the normative form of the law in this repo; the Go implementation is proven against that corpus, never against hand-copied expectations.

Tech Stack: Go 1.27.2 (this VM: ~/sdk/go); stdlib only for the codec (crypto/sha256, custom encoder — encoding/json defaults do not match the law); Python 3.12 for corpus generation tooling only (held outside this repo, never shipped); corpus format = JSON files under testdata/corpus/.

Spec: the features development plan for the replay capability (AEP goal workspace, 2026-11-18) §4 F1, §6 Phase 0, §7 (canonical-divergence risk), and the reverse-engineering findings held with it. The in-repo normative form of the canonical law is the conformance corpus under testdata/corpus/ (corpus v2) together with the Global Constraints below.

Global Constraints

  • Corpus discipline: the corpus under testdata/corpus/ is the normative form of the law in this repo. Its manifest records the corpus version and the law versions it pins; any regeneration is a new corpus version, reviewed as such. Generation tooling and its reference inputs are held outside this repo.
  • Two profiles, never conflated: the kernel profile = prefix "replaycore.kernel.canonical.v1\n", ensure_ascii=False (raw UTF-8), compact separators ( ",", ":" ), keys sorted by Unicode code point, allow_nan=False. The commons profile = prefix "commons.canonical.v1\n", ensure_ascii=True (lowercase \uXXXX), floats/bytes/sets/tuples forbidden. A digest is always sha256:<lowercase hex> of prefix + canonical bytes.
  • Record identity (v2): digest input is exactly {body, caused_by, kind:"record", mode, schema_ref, witness}; caused_by order is identity (reordering changes the digest); record_id == digest. Path, ordinal, receipt, and kind_label are excluded from identity.
  • Root witness law: the empty witness sentinel "" is legal only for the root witness record (schema_ref == "kernel.witness.root.v1", mode capture, no causal parents, body exactly root_witness_body()). Ground truth verified 2026-11-18 against the fork's own code: root_witness_body_digest = sha256:22e3bf15…85721130, root_witness_record_id = sha256:0b67497c…2fd6310.
  • Claims discipline: every capability statement in any doc produced by this phase cites the test that proves it. No upstream performance or cache numbers anywhere.
  • Memory rule: replay-core is an execution store, not a memory system. Nothing in this phase touches NeuroStrata except, at phase close, a pointer inscription (plan + corpus locations) in the aep namespace.
  • Build discipline (this VM): ~1.5 GiB effective memory; Go builds are light, keep them that way — stdlib only, no cgo in this phase. GOTMPDIR=$HOME/.gotmp for any large build step.
  • Repo mechanics (once D2 lands): Conventional Commit subjects; all GitHub calls through ghg with GHG_ACTOR=replay-core-phase0; PRs target develop if the home is AEP; merges only on Pratik's per-PR word; planning documents ship in the PR under docs/plans/.
  • TDD check scripts live in /tmp during execution (never committed), per the pipeline. The phase gate script is specified in Task 5 and prototyped at ~/workspace/goals/autonomous-code-defense-factory/hidden_files/replay-core/check-phase0.sh.

Review Focus

The five input classes most likely to bite, each pinned to its owning task's tests:

  1. Float formatting divergence (kernel profile only): Python repr shortest-round-trip vs Go formatting — exponent forms (1e+21 vs 1e21), 1.0 vs 1, -0.0, subnormals. A silent mismatch corrupts every digest downstream. → Task 3.
  2. Integers beyond int64/uint64: Python ints are unbounded; a body carrying 9007199254740993 (in the v1 vectors) or larger must digest identically, not saturate or fall back to float64. → Task 3.
  3. Unicode key ordering and escaping: keys sort by code point (not byte-wise UTF-16 units — astral-plane keys expose this); the kernel profile emits raw UTF-8 (snowman bytes \xe2\x98\x83), v1 escapes. Wrong in either profile = wrong digests only for non-ASCII payloads, i.e. exactly the payloads tests forget. → Task 2.
  4. Non-finite and out-of-law values: NaN/±Inf must be rejected in both profiles; floats must be rejected in v1 with a typed error naming the JSON path (upstream: TypeError … at $.a[0]). Accepting one silently forks the law. → Tasks 2–3.
  5. Witness/root-sentinel misuse: empty witness on a non-root record, root schema with a non-empty witness, root body differing by one field — each must be a hard validation error before any digest is computed, matching upstream's ValueError cases one-for-one. → Task 4.
